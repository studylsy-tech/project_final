## 🚀 이클립스 Git & 브랜치 협업 가이드

### 📍 핵심 요약 프로세스
1. **처음 시작 시**: [Branch 생성 및 서버 등록] ➡️ [Master 최신화(Pull)]
2. **작업 시작 전**: [Master 최신화(Pull)] ➡️ [내 Branch로 이동]
3. **코드 수정 시**: [내 Branch로 이동] ➡️ [코드 수정] ➡️ [Commit & Push] ➡️ [Merge]

---

### 🟢 1단계: 나의 비밀 작업실 만들기 (초기 설정)
원본 코드를 보호하기 위해 나만의 복사본 공간을 먼저 확보해야 합니다.
* **브랜치 생성**: 프로젝트 우클릭 ➡️ Team ➡️ Switch To ➡️ **New Branch...**
* **서버 등록**: 생성 직후 Team ➡️ **Push to Origin** (서버에 내 이름을 등록하는 과정)
* **Master Pull**: Git Repositories 창에서 master 더블클릭 ➡️ **Pull** (가장 깨끗한 최신 상태 확보)

### 🔵 2단계: 출근 도장 찍기 (동기화)
다른 팀원이 만든 최신 코드를 내 컴퓨터로 가져오는 과정입니다.
* **Master 이동**: Git Repositories 창에서 **master** 더블클릭
* **최신화(Pull)**: master 우클릭 ➡️ **Pull** 실행 (남들이 수정한 내용 가져오기)
* **내 공간 이동**: 작업 전, 다시 내가 만든 **내 브랜치**를 더블클릭하여 이동

### 🟠 3단계: 실제 작업 및 보고하기 (구현 및 통합)
실제로 코드를 짜고 전체 결과물에 합치는 핵심 단계입니다.
* **코드 수정**: 내 브랜치인지 확인(프로젝트 옆 이름 확인) 후 Java/JSP 코드 작성
* **기록(Commit)**: Git Staging 창에서 파일을 **+** 버튼으로 올리고 작업 메시지 작성
* **전송(Push)**: **Commit & Push** 클릭 (서버로 내 작업 전송)
  * 💡 Tip: 창에 파일이 안 뜨면 다시 **Pull**을 눌러보세요.
* **합치기(Merge)**: 
  1. 다시 **master** 브랜치로 이동
  2. Team ➡️ **Merge...** ➡️ 내 브랜치 선택 ➡️ Merge 클릭
  3. 합쳐진 master를 다시 **Push**하여 최종 업데이트

---

### ⚠️ 주의사항 (당황하지 마세요!)
* **[Rejected] 메시지**: 누군가 나보다 먼저 코드를 올린 상태입니다. **master**로 이동해 다시 **Pull**을 받고 내 작업을 합치면 해결됩니다.
* **[브랜치 확인]**: 코드를 짜기 전, 프로젝트 옆 괄호 안의 이름이 내 브랜치인지 반드시 확인하세요.
